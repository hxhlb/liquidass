Scope: stock system keyboard; enabled; Enhanced renderer + system blur. User
reports changed styling but mainly a blurred background.

  host=Keyboard src=321x273 dst=321x273 radius=25.59 bezel=13.00

The custom-render path is reached with the keyboard shader marker and compatible
destination. The log point precedes command encoding; it does not prove every
GPU submission or the final composited pixels. No unusable-destination message
for the keyboard appears in this log. Startup filter-table retries eventually
complete, so they do not establish a persistent registration failure.

The keyboard surface exposes Keyboard.SpecularEnabled (per-engine storage), with
the same default-on UI contract as other highlight switches. Installation had
unconditionally set glass.lgSpecularEnabledOverride=@NO. That prevented the
switch from affecting keyboard glass. 52 reads the existing preference and
applies its boolean on every update, including an existing glass after a reload.
Missing/invalid values use the setting's advertised YES default. Explicit NO is
retained. No host-default table, shared shader/blur path, tint, key rendering,
input geometry or font preference is changed.

tests/test_keyboard_specular.py fails on the old forced-off production block and
compiles the new override block to verify default/on/off/invalid values and
updates on the same view. Renderer-profile and highlight update regressions
cover existing preference mapping and layer update behavior. Native iOS 18.6
keyboard hierarchy and standalone GPU shader checks from the earlier diagnostic
step remain supporting evidence, not physical-device validation of build 52.
